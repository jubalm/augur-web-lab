# Project purpose

September 13 contact refinement: Talk to us opens `/contact/`, with welcoming copy about Augur products, Discord, socials and a form. September 14 structure-review refinement makes every external action, including `contact@augur.net`, an inert placeholder. Name, Email and Message are required; Company / project and Website are optional. Send message demonstrates local validation without submitting data or opening an email app. The inbox requires domain-owner provisioning or confirmation; website-native delivery requires an endpoint. This supersedes the earlier absence of secondary website pages below; the full current composition is recorded in `website-strategy.md`.

Augur Web Lab is the workshop. `/` is a local first-version experiment containing the Augur header, hero, Why + how, the remaining homepage sections and a footer. Shared low-level document setup does not imply shared visible navigation or footers.

`/lab` holds specimens, fixed control examples, and the full Signal Loom study. The homepage combines its original proposed headline and support with the About / Products / Resources / Community header, two actions (Explore Augur Lituus, still a placeholder, and Read the whitepaper, which opens the published paper), a light/dark switch, and an interactive loom. About is a standalone placeholder. Products opens Augur Lituus / Zoltar / Augur Stratoblast. Resources opens Blog / FAQ / Learn / REP / Whitepaper. The header's Whitepaper item and all other resource and product destinations are placeholders. Community shows inert Discord / Telegram / X / GitHub placeholders. The hero has a 1.5-second staged arrival and a static tonal background. Signal Loom moves while visible, responds to pointer and keyboard input, and pauses with Escape; reduced motion keeps a static composition. There is no playback toolbar. Contact is the only built secondary website page; the homepage sections are built, while product/content pages remain proposals; the former `/homepages` tree remains deleted. The lab retains its chooser. This experiment has not been promoted to production, and its effect on visitor comprehension remains unmeasured.

The Brand Foundation PDF and shared design-system implementation remain references. Explicit user requests can authorize local experiments; current exceptions are neutral typography, bright green action fills in both themes, and square 48 px controls, semibold labels, bold outlined icons, filled fields, and Crimson errors. They do not rewrite upstream primitives.

Astro supplies static HTML. Native scripts handle the chooser, theme, finite homepage motion, the lab motion study, and loading previews. React renders the unchanged shared Button and Input specimens without hydration. There is no backend or data collection. Mobile design and QA are deferred at the user's request.
