# Project purpose

September 13 contact refinement: Talk to us opens `/contact/`, with welcoming copy about Augur products, Discord, official socials and a form that composes email to `contact@augur.net`. Name, Email and Message are required; Company / project and Website are optional. The visitor finishes sending in an email app. The inbox requires domain-owner provisioning or confirmation; website-native delivery requires an endpoint. This supersedes the earlier absence of secondary website pages below; the full current composition is recorded in `website-strategy.md`.

Augur Web Lab is the workshop. `/` is a local first-version experiment containing the Augur header and hero. Shared low-level document setup does not imply shared visible navigation or footers.

`/lab` holds specimens, fixed control examples, and the full Signal Loom study. The homepage combines its original proposed headline and support with the Products / Developers / Resources / Blog / FAQ header, two public-source actions, a light/dark switch, and an interactive loom. Products opens Augur Lituus / Zoltar / Augur Stratoblast. Product and resource destinations are placeholders; Resources opens Learn / REP / Research / History. The hero has a 1.5-second staged arrival and a static tonal background. Signal Loom moves while visible, responds to pointer and keyboard input, and pauses with Escape; reduced motion keeps a static composition. There is no playback toolbar. Contact is the only built secondary website page; lower homepage sections and other product/content pages remain proposals; the former `/homepages` tree remains deleted. The lab retains its chooser. This experiment has not been promoted to production, and its effect on visitor comprehension remains unmeasured.

The Brand Foundation PDF and shared design-system implementation remain references. Explicit user requests can authorize local experiments; current exceptions are neutral typography, bright green action fills in both themes, and square 48 px controls, semibold labels, bold outlined icons, filled fields, and Crimson errors. They do not rewrite upstream primitives.

Astro supplies static HTML. Native scripts handle the chooser, theme, finite homepage motion, the lab motion study, and loading previews. React renders the unchanged shared Button and Input specimens without hydration. There is no backend or data collection. Mobile design and QA are deferred at the user's request.
